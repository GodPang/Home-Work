# Home-Work

一个能在浏览器里直接用的家装户型设计工具：2D 平面布置 + 家具摆放 + 材料估价 + 3D 漫游。

在开源项目 [Furnish](https://github.com/oxomkbk/Furnish) 的基础上，加了**自定义户型**能力——你可以把自己的房子导进来，而不是只能在内置的那十几套里挑。

## 直接用

双击 `index.html` 就行，不需要构建、不需要联网。

> 若浏览器拒绝加载同目录的 `cp-*.js`（个别安全策略），在该目录起一个静态服务即可：
> `python -m http.server 8000` → 打开 `http://localhost:8000/index.html`

## 加了什么

| 能力 | 说明 |
| --- | --- |
| **导入 CAD（DXF）** | 拖进 `.dxf`，自动识别墙 / 门 / 窗 / 房间，带图层映射向导和实时预览 |
| **图片描图** | 上传户型图做底图，标定比例尺后手工描墙画房间 |
| **结构自由编辑** | 已导入的户型随时改墙、开门开窗、重分房间，已摆好的家具不会丢 |
| **户型管理** | 重命名 / 复制 / 导出 JSON / 删除；底图只存本机 IndexedDB，不进导出和分享链接 |

## 文件结构

```
index.html      原版 Furnish，只在末尾多引了 5 个脚本，其余一行没动
cp-core.js      存储层（localStorage + IndexedDB）、几何引擎、校验器
cp-dxf.js       DXF 解析器 + 图层映射向导
cp-trace.js     图片描图编辑器（也用于编辑已有户型的结构）
cp-ui.js        户型库入口、管理菜单、导入导出、分享链接扩展
cp-preset.js    内置的一份示例户型（由 CAD 图纸导入生成）
gen-preset.js   从 DXF 重新生成 cp-preset.js
verify-preset.js 校验生成的户型是否符合 Furnish 的数据约定
peek-dxf.js / render-plan.js / zoom-plan.js / render-source.js / dbg-wins.js
               零依赖调试工具：把 DXF 或户型画成 PNG（手写 PNG 编码），用来肉眼核对
使用说明-自定义户型.md  完整使用说明
```

## 导入 CAD 是怎么识别的

家装图纸不是 BIM 模型，墙门窗房间都得从一堆线段里反推。管线顺序是：

1. **窗** —— CAD 里窗常画成 3~7 条平行线，用并查集按「间距小 + 长度方向重叠」聚成簇，一簇 = 一个窗
2. **墙** —— 两条平行线配对，间距即墙厚（不再是固定厚度），贪心取重叠最长的一对
3. **补缝** —— 墙角、门垛、窗边之间的小缝补上，保证房间能闭合
4. **门** —— 先找门弧（圆心=铰点、半径=门宽）；没有弧就看墙段缺口；再没有就看 `MH:xxxx` 这类文字标注
5. **房间** —— 墙+门+窗做成掩膜，形态学闭运算补缝，泛洪提取轮廓，道格拉斯-普克抽稀
6. **镜像** —— CAD 的 Y 轴朝上、这里 Y 轴朝下，整体沿 Y 轴翻一次

几个容易踩的坑，代码里都有对应处理：

- 中文图层名是 GBK 编码的，按 UTF-8 → GB18030 依次尝试解码
- 「墙体拆改后定位图」这类图纸里，图层 `0` 会混着**拆改前原墙位置的参考单线**，
  直接补成墙会把房间和它的窗隔开。现在的规则是：与成墙平行、间距 < 900mm、纵向重叠过半的单线不补墙
- 门的推断会把窗也算进墙段，否则「门」会跨过中间的窗

## 内置的示例户型

仓库里 `cp-preset.js` 是一份真实图纸的识别结果，可以直接点开用：
**墙 35 · 门 2 · 窗 8 · 房间 3**，外框 14.65 × 9.93 m。

| 房间 | 面积 | 地面材质 |
| --- | --- | --- |
| 客餐厅（含开放厨房与过厅） | 93.61 ㎡ | 800 地砖 |
| 主卧 | 18.18 ㎡ | 橡木地板 |
| 卫生间 | 4.57 ㎡ | 300 防滑砖 |

想换成自己的图纸：

```bash
# 1. DWG 是二进制，先转 DXF（浏览器读不了 DWG）
#    用 LibreDWG 的 WASM 版本在 node 里转，见「使用说明」文档
# 2. 生成
node gen-preset.js      # 默认读 文昌.utf8.dxf，改脚本里的文件名即可
node verify-preset.js   # 十几项数据校验，末尾应全是 ✓
```

## 已知限制

- **DWG 必须先在 CAD 里另存为 DXF**，浏览器读不了二进制 DWG
- 识别算法目前只在少数几张国产家装图上验证过，遇到别的画法可能需要调「图层映射」里的参数
- 门窗/拆改记录是按数组下标存的，**改了户型结构后旧的开启方向会错位**
- 分享链接里自定义户型会带上户型数据，户型很大时会提示改用「导出户型 JSON」
